Project overview

SmartWaste

A waste reporting and collection planning platform that helps communities identify bins that need attention and helps collection teams plan efficient pickups.

1. Problem Statement: What problem does SmartWaste solve, and who is it for?

  • Collection teams often lack timely information about which bins are filling up and which should be serviced first.
  • This can result in overflowing bins, unnecessary pickups, and inefficient collection routes.
  • SmartWaste gives teams current reports and forecasts so they can prioritize urgent bins and plan collections more effectively.
  • Residents and volunteers can report a bin using a photo or a manual fill-level selection.
  • Collection crews and dispatchers can review bin status, create routes, and track completed stops.

2. What the project does

  • Offers a Report & Upload workspace for residents and volunteers, and a Field Operations & Dispatch workspace for collection teams.
  • Shows demo bins on a map with place names and route overlays.
  • Accepts bin photos and estimates fill levels. Amazon Rekognition checks labels in the image; a built-in image heuristic estimates how full the bin is.
  • Forecasts whether a bin may overflow before the next collection period.
  • Ranks bins by urgency and builds a collection plan within the truck's capacity.
  • Can calculate a road-following route through planned stops and lets crews track completed stops.
  • Can send alerts about overflow risks and completed nightly plans.
Project scope: The current setup uses demo data for one neighbourhood. SageMaker support is optional; a trained model or SageMaker endpoint is not currently deployed.

3. How AWS is used

AWS open-source tools and libraries

  • AWS Cloud Development Kit (AWS CDK): defines and deploys AWS infrastructure as TypeScript code.
  • Boto3: Python SDK used by backend Lambda functions to call AWS services.
  • Pillow: open-source Python image library packaged as a Lambda layer to decode and process uploaded photos.

AWS services

Amazon S3

Hosts the static website and stores privately uploaded bin photos.

Amazon API Gateway

Provides the HTTP API used by the frontend to reach the backend.

AWS Lambda

Runs the API, image analyzer, collection-planning steps, and seed-data handler.

Amazon DynamoDB

Stores bin records, reports, settings, and collection plans.

Amazon SQS

Queues photo upload events for processing and sends repeated failures to a dead-letter queue.

AWS Step Functions

Coordinates the Express workflow that runs the nightly collection planner.

Amazon EventBridge

Starts the scheduled planner and routes application events such as overflow and plan-ready notifications.

Amazon SNS

Sends email alerts when configured and notifies on planner failures.

Amazon Rekognition

Checks uploaded photos for labels associated with bins and waste.

Amazon Location Service

Provides map tiles and road-following route geometry.

Amazon Cognito Identity Pools

Provides temporary guest credentials for browser map access.

Amazon CloudWatch

Collects logs and metrics and provides dashboards and alarms for the API, photo pipeline, and planner.

Amazon SageMaker (optional)

If an endpoint is configured, the analyzer can request a fill-level estimate. No endpoint or trained model is currently deployed.

4. Tech stack

  • Frontend: HTML, CSS, and JavaScript.
  • Backend: Python 3.12 on AWS Lambda.
  • Infrastructure as code: TypeScript and AWS CDK v2.
  • Image processing: Pillow, a built-in edge-density fill estimator, and Rekognition image-label checks.
  • Data and file storage: DynamoDB and Amazon S3.
  • Mapping and routing: Amazon Location Service, combined with demo logic to select and order collection stops.

5. Architecture

1
Website and API

The browser loads the static app from S3. API requests go to API Gateway, which invokes the API Lambda. The API reads and writes application data in DynamoDB.

2
Photo reporting

The API creates an upload record and returns a presigned S3 upload. S3 sends an object-created event to SQS, which triggers the analyzer Lambda. The analyzer checks the photo, estimates fill level, updates DynamoDB, and can publish an overflow event.

3
Collection planning

EventBridge starts the Step Functions workflow nightly. Lambda steps load and score bins, select stops within truck capacity, optimize their order, and save the plan in DynamoDB.

4
Maps and routes

The browser uses temporary Cognito guest credentials to load Amazon Location maps. The planner can request road-following route geometry from Amazon Location Routes.

5
Alerts and monitoring

EventBridge routes application events to SNS notifications. CloudWatch collects logs and metrics and provides a dashboard and alarms for system health.
